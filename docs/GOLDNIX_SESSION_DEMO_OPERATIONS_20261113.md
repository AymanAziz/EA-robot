The selected implementation is a resident `OnStart` script; EA lifecycle facts below are identified separately.

## Startup lifecycle

MT5 accepts `/config:<Windows path>`; invalid assignments can fall back to defaults. Two terminal copies cannot run from the same installation directory.

`[StartUp] Expert` resolves under `MQL5\Experts`; `Script` resolves under `MQL5\Scripts`. Their `ExpertParameters`/`ScriptParameters` files belong in **`MQL5\Presets` in the data directory**, unlike tester presets. Specify `Symbol=XAUUSD.c` and Period. The additional startup chart is not saved for reopening without that configuration. Without Symbol, the first profile chart is used; without charts, the program does not start. Unspecified parameter files use code defaults. `ShutdownTerminal` applies **only to scripts**, after they finish. `[Experts] Enabled` and `AllowLiveTrading` govern EA use and automated trading; the latter name is not an account-type guard. [MetaQuotes platform startup](https://www.metatrader5.com/en/terminal/help/start_advanced/start).

**Implementation consequence:** validate paths, hashes, account/inputs and startup acknowledgement; serialize launches. Supply the startup configuration on every daily invocation. Script completion must follow confirmed closure before automatic terminal shutdown is enabled.

## DEMO guard and ownership

MetaQuotes exposes `ACCOUNT_TRADE_MODE_DEMO`, `ACCOUNT_LOGIN`, `ACCOUNT_SERVER`, account currency and trade permissions. Require the exact expected demo identity and verified symbol contract before allowing operations, then recheck at execution boundaries. Account changes also reinitialize an EA; the guard belongs in initialization and the operational path. [Account properties](https://www.mql5.com/en/docs/constants/environment_state/accountinformation), [terminal events](https://www.mql5.com/en/docs/runtime/event_fire).

Ownership should require symbol, dedicated magic and the recorded position identifier. `POSITION_IDENTIFIER` links the lifecycle's orders/deals; `POSITION_TICKET` can change after server service operations, so rediscover the current ticket. Refresh `PositionSelectByTicket` immediately before reading properties because earlier selected data can be stale. [Position properties](https://www.mql5.com/en/docs/constants/tradingconstants/positionproperties), [position selection](https://www.mql5.com/en/docs/trading/positionselectbyticket).

Close by **ticket**, after checking ownership. The symbol overload can close the lowest-ticket position on a hedging account. A true `CTrade::PositionClose` return means its basic structures passed validation, not that the broker completed closure: check `ResultRetcode`, then fresh position/deal state. Netting allows one combined position per symbol, so a magic number cannot separate another trader's contribution to a mixed position; refuse ambiguous ownership. [CTrade PositionClose](https://www.mql5.com/en/docs/standardlibrary/tradeclasses/ctrade/ctradepositionclose).

Persist the ownership ledger, active position metadata, daily risk state and last processed signal across restarts. Restarting must not clear a halt, duplicate an entry or adopt unrelated trades. Put accepted SL/TP on the server: MetaQuotes documents that these remain independent of the running terminal. Their presence does not implement a 06:30 timed close. [Protective orders](https://www.metatrader5.com/en/terminal/help/trading/performing_deals).

## Time, timer and shutdown

Live `TimeGMT()` derives UTC from the computer's clock and timezone/DST settings. In the Strategy Tester it instead equals simulated server time. Verify Wine/terminal UTC against the host clock at startup; do not reuse the tester's clock assumption. Live `TimeCurrent()` outside OnTick is the timestamp of the last Market Watch quote, so it can stop advancing without quotes. It is unsuitable as the sole wall-clock deadline. [TimeGMT](https://www.mql5.com/en/docs/dateandtime/timegmt), [TimeCurrent](https://www.mql5.com/en/docs/dateandtime/timecurrent).

Compute explicit UTC start/end timestamps from the Malaysia session date, then pass and log them. For example, November 13 00:00–06:30 Malaysia corresponds to November 12 16:00–22:30 UTC. Validate `start <= now < end` for new entries on every launch/resume and immediately before an order. Keep bar-time conversion separate from the wall-clock session.

`EventSetTimer` normally runs from OnInit and `EventKillTimer` from OnDeinit. Timer events are generated periodically without requiring new ticks, but each EA has one event queue: a pending or running Timer event prevents another being queued. Long handlers delay deadline work. [OnTimer](https://www.mql5.com/en/docs/event_handlers/ontimer).

At the cutoff, latch entry-disabled state, request closure of owned positions, record each result and retry through subsequent timer/watchdog checks until closure is confirmed. `ExpertRemove` schedules removal after the current handler; later events are not processed. It does not itself close positions. `OnDeinit` is forcibly limited to 2.5 seconds, so it cannot be the main flatten/retry mechanism. Unload or shut down only after confirmed flatness, or explicitly record unresolved exposure while keeping management active. [ExpertRemove](https://www.mql5.com/en/docs/common/expertremove), [deinitialization limit](https://www.mql5.com/en/docs/runtime/event_fire).

For the selected resident script, `OnStart` is its only event handler: it receives no OnTick, OnTimer or OnDeinit events. Put guards, polling, closure and cleanup directly in its bounded loop; use an integer result for the completion journal. `Sleep(100)` yields execution but is not an exact 100 ms deadline guarantee. `IsStopped` requires prompt termination; forced removal allows only about three seconds, not an extended liquidation loop. Therefore finish normal closure before returning and retain an independent watchdog for forced termination. [OnStart](https://www.mql5.com/en/docs/event_handlers/onstart), [Sleep](https://www.mql5.com/en/docs/common/sleep), [IsStopped](https://www.mql5.com/en/docs/check/isstopped).

The cutoff is a control target, not a guaranteed fill time during disconnection or a closed market. A watchdog should reconcile heartbeat, account identity and owned positions, retaining the server protections while closure is unresolved. It must not treat killing the terminal as closing a position.

## Broker session boundary can precede 06:30

`SymbolInfoSessionTrade` returns the trading windows for a symbol and weekday; enumerate session indices from zero until false. Use trading sessions, not merely quote sessions. The official AlgoBook places these times in the **broker/server timezone** and explicitly warns that raw `to` values can be **86,400 seconds or greater**, representing midnight or a next-day close. Preserve this day component instead of formatting to HH:MM or reducing modulo 86,400. [Session API](https://www.mql5.com/en/docs/marketinformation/symbolinfosessiontrade), [MetaQuotes session interpretation](https://www.mql5.com/en/book/automation/symbols/symbols_sessions).

Engineering recommendation: construct dated intervals from server midnight plus raw offsets, including the previous weekday's intervals for overnight carry; test `start <= now < end`. Archive all raw fields and the verified current server offset. Do not interpret ambiguous zero-length intervals as permission for 24-hour trading. Missing/invalid session data should block new entries while preserving owned-position management. A weekly table is not proof against exceptional closures; execution responses remain authoritative.

The currently accessible JustMarkets commodities page lists **unsuffixed XAUUSD** daily break **23:58–01:01 server GMT+2**, Monday opening 01:02 and Friday closing 23:58. At +2, that daily break corresponds to **05:58–07:01 Malaysia**, containing 06:30. The page redirects to the provider's regional domain. This generic listing motivates checking the actual `XAUUSD.c` table; it does not establish this account's exact schedule. [JustMarkets commodities](https://justmarkets.com/markets/commodities).

The selected operational rule is to flatten at `min(user_end_utc, active_trade_session_end_utc - 120 seconds)`, then continue observation until 06:30. The 120 seconds is a declared operational allowance, not a researched optimum or a fill guarantee. Latch new entries off when that earlier cutoff arrives, including after restart; do not re-enter if a later broker session opens before 06:30. Record the actual cutoff and reason in each session report.

## Tick warmup and live continuity

`CopyTicksRange` returns oldest-first ticks with **inclusive millisecond bounds**. A timeout can return available partial data; a small static buffer truncates with error 4407, and dynamic arrays can exhaust memory. Record the return count and immediately captured error, validate coverage/gaps, and reject incomplete warmup for entries. For half-open hour windows, request through the next hour's millisecond minus one. [CopyTicksRange](https://www.mql5.com/en/docs/series/copyticksrange).

The related `CopyTicks` documentation explicitly allows an EA/script call to wait **45 seconds** for synchronization and return available ticks while synchronization continues. That page describes cache/memory/disk access costs and notes filtering flags do not confer a significant speed advantage. The Range reference documents timeout/partial behavior but does not independently specify that numerical timeout; do not present 45 seconds as a guaranteed Range bound. [CopyTicks](https://www.mql5.com/en/docs/series/copyticks).

Warm up in bounded chunks before permitting entries; cache completed bars rather than repeatedly downloading the entire window. Check the deadline before and after any blocking call. Avoid warmup requests in the close-first path. Preserve H01's separate Bid/Ask OHLC aggregation and closed-bar eligibility; do not substitute native Bid-only H1 bars silently.

Live OnTick can represent multiple received ticks, unlike the generated tester sequence. Recover missing updates through incremental tick queries. Because timestamps are not unique, preserve same-millisecond records and use overlap plus a boundary occurrence cursor rather than dropping all records sharing the last timestamp. Never execute stale historical signals as catch-up orders. [CopyTicks event semantics](https://www.mql5.com/en/docs/series/copyticks).

## macOS scheduling and wake behavior

Use a per-user LaunchAgent for the GUI/Wine session; user agents execute while that user is logged in. `StartCalendarInterval` with Hour 0 and Minute 0 specifies daily midnight, with omitted fields acting as wildcards. `RunAtLoad=true` additionally invokes the wrapper when the job loads; it is not a midnight-only rule. Use absolute argument paths, explicit working directory and logs. Keep the wrapper idempotent with one active-session lock and session ledger. [Apple agents](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html), [Apple launchd plist reference](https://github.com/apple-oss-distributions/launchd/blob/main/man/launchd.plist.5).

A missed calendar launch during sleep runs on wake; multiple missed events coalesce. If the Mac was powered off, the calendar event is not automatically replayed at boot. RunAtLoad can provide a separate login recovery invocation, subject to the same session gate. Neither mechanism promises waking the computer at midnight. Verify the scheduler's host timezone; setting a child process's `TZ` is not evidence that launchd's calendar changed. [Apple scheduling](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/ScheduledJobs.html), installed `launchd.plist(5)`.

`caffeinate -i` prevents idle system sleep while active; `-s` applies on AC power. A utility-scoped assertion lasts for that utility, and its `-t` timeout is documented as ignored when a utility is supplied. Therefore keep the session supervisor alive through confirmed closure, or manage a separate bounded assertion. `caffeinate open …` only covers the launcher if it exits immediately; it is not a persistence guarantee for MT5. These assertions do not establish operation through power loss, logout or every lid-close condition. [Apple caffeinate manual](https://github.com/apple-oss-distributions/PowerManagement/blob/main/caffeinate/caffeinate.8).

The daily review artifact should show scheduled/actual start and end, ready/no-trade reasons, quote and heartbeat gaps, all owned deals and costs, risk halts, close attempts and final exposure. Report unavailable or incomplete sessions explicitly; do not count them as successful zero-trade sessions.
